MCP: el estándar que conecta la IA con tus sistemas (y cómo usarlo sin abrirle la puerta a atacantes)

Qué es el Model Context Protocol, por qué se convirtió en el "USB-C de la IA" y qué controles aplicar antes de conectar un servidor MCP a los datos de tu empresa.

En este artículo

    Hasta hace poco, conectar un asistente de IA con los sistemas de una empresa significaba construir una integración a medida por cada combinación de modelo y herramienta: una para el CRM, otra para la base de datos, otra para el gestor documental. Con varios modelos y decenas de sistemas, el número de integraciones crece rápido y cada una se mantiene por separado.

    El Model Context Protocol (MCP) nació para resolver exactamente ese problema.

    Qué es MCP

    Anthropic presentó MCP el 25 de noviembre de 2024 como un estándar abierto para conectar asistentes de IA con los lugares donde viven los datos: repositorios de documentos, herramientas de negocio y entornos de desarrollo. Junto con el anuncio publicó servidores listos para Google Drive, Slack, GitHub, Git, Postgres y Puppeteer [1].

    La propia documentación del protocolo lo explica con una analogía que se volvió popular: MCP es como un puerto USB-C para aplicaciones de IA. Así como USB-C estandariza cómo se conectan los dispositivos, MCP estandariza cómo una aplicación de IA se conecta con sistemas externos [2]. Hoy lo soportan asistentes y herramientas como Claude, ChatGPT, Visual Studio Code y Cursor, entre muchos otros [2].

    Cómo funciona

    La arquitectura tiene tres piezas [3]:

    • Host: la aplicación que usa la persona, como un asistente de escritorio, un IDE o el chat interno de tu empresa.
    • Cliente: el componente dentro del host que mantiene la conexión con cada servidor.
    • Servidor: el programa que expone capacidades de un sistema concreto, por ejemplo tu ERP.

    Un servidor puede ofrecer tres tipos de capacidades: herramientas que el modelo puede invocar ("crear ticket", "consultar saldo"), recursos que aportan contexto (documentos, registros) y prompts o plantillas reutilizables. La comunicación usa JSON-RPC, ya sea de forma local mediante entrada y salida estándar (stdio) o remota mediante HTTP.

    La consecuencia para una empresa es importante: construyes un servidor MCP para tu sistema una sola vez y cualquier aplicación compatible puede usarlo.

    El protocolo maduró en seguridad

    MCP evoluciona mediante revisiones fechadas de su especificación. La revisión del 18 de junio de 2025, por ejemplo, clasificó a los servidores MCP como resource servers de OAuth, añadió metadatos para descubrir el servidor de autorización correspondiente y exigió a los clientes usar resource indicators (RFC 8707) para evitar que un servidor malicioso obtenga tokens destinados a otro [4]. También incorporó salidas estructuradas de herramientas y la capacidad de que un servidor solicite información adicional al usuario durante una interacción.

    Esto es clave: un servidor remoto expuesto a internet debe tratarse como cualquier API corporativa, con autenticación, autorización y auditoría.

    Los riesgos que más me preocupan

    El modelo decide qué herramienta usar leyendo su descripción. Eso convierte la descripción en una superficie de ataque. En abril de 2025, Invariant Labs documentó los tool poisoning attacks: instrucciones maliciosas escondidas en la descripción de una herramienta, visibles para el modelo pero no para el usuario, capaces de inducirlo a leer archivos sensibles y filtrarlos [5]. El mismo trabajo describe dos variantes:

    • Rug pull: un servidor cambia la descripción de sus herramientas después de que el usuario lo aprobó.
    • Shadowing: un servidor malicioso altera cómo el agente usa las herramientas de otro servidor confiable.

    Si sumas a esto la "agencia excesiva" del OWASP Top 10 para LLM [6], el resultado es claro: conectar servidores MCP de terceros sin revisión es equivalente a instalar dependencias desconocidas con acceso a tus datos.

    Checklist antes de conectar un servidor MCP

    • Inventario y procedencia. Usa solo servidores de fuentes confiables o construidos por tu equipo, y revisa su código.
    • Fija versiones. Fijar versión o hash de servidores y herramientas permite detectar cambios no autorizados en sus descripciones, como recomienda Invariant Labs [5].
    • Mínimo privilegio. Cada servidor recibe credenciales propias, con permisos de solo lectura salvo que la escritura sea indispensable.
    • Confirmación humana para cualquier herramienta que modifique datos, envíe información o mueva dinero.
    • Aislamiento entre servidores. Evita que un mismo agente combine acceso a datos internos, contenido externo y un canal de salida.
    • Autenticación OAuth y auditoría en servidores remotos, con registro de cada llamada a herramienta.

    En resumen

    MCP es probablemente la forma más eficiente de conectar la IA con los sistemas de una empresa: estándar, abierta y con un ecosistema enorme. Pero un servidor MCP no es un plugin inocente; es una puerta hacia tus datos. Trátalo con el mismo rigor que una API en producción y obtendrás la velocidad del estándar sin heredar sus riesgos.
